# session-to-skill Design Spec

**Version:** v1.0  
**Date:** 2026-06-26  
**Status:** Approved

---

## 目标

在项目会话自然结束时，自动从当前对话提炼项目专属 skill，以 markdown 展示在对话末尾。用户确认后自行保存。随着会话积累，skill 库有结构地生长，不堆叠。

---

## 触发逻辑

满足以下任一条件时触发 skill 生成：

1. **明确结束语** — 用户发出独立的收尾消息（完成了 / 谢谢 / 收工 / done / 就这样 / 好了）
2. **任务自然闭合** — 主要任务已完成，无 pending 需求，最后几条消息为确认/验收性质
3. **用户主动触发** — 用户说"生成 skill"/"总结一下这次"/"帮我提炼 skill"

触发后在当前响应末尾用 `---` 分隔线追加 skill 内容，不打断正常回复。

---

## 提炼逻辑

扫描本次完整对话，只提炼**明确出现的信号**，不推断，不猜测。

### 项目约定（Project Conventions）

提炼条件（满足其一）：

- 用户纠正了 Claude 的做法
- 用户明确确认了某个非显而易见的选择
- 出现了技术选型、文件结构、命名规则的显式决策

### 协作偏好（Workflow Preferences）

提炼条件（满足其一）：

- 用户要求了特定工作流步骤
- 用户明确排斥某种行为
- 同一操作模式在对话中出现 ≥ 2 次

### 过滤规则

- 一次性上下文不提炼（如"这个文件帮我改一下"）
- 出现 ≥ 2 次的模式优先级更高
- 模糊信号不录入，宁少勿滥

---

## 分类路由

生成前先扫描 `~/.claude/skills/<project>-skills/` 下所有已有文件的 `description` 字段，按以下决策树路由每条内容：

```
对于每条提炼出的内容：

1. 已有完全相同或高度相似的条目？
   → 跳过（去重）

2. 有 description 语义匹配的已有文件，且行数 < 200？
   → 追加到该文件

3. 有匹配文件但行数 ≥ 200？
   → 拆分：保留 SKILL.md 作总览，重内容移入 reference/topic.md
   → SKILL.md 更新 description，收窄职责范围
   → 新子文件写好自己的 description

4. 没有匹配的已有文件？
   → 新建文件，动名词命名，写好 description
```

当项目 skill 文件达到 2 个或以上时，维护 `<project>-skills/INDEX.md`，列出所有子文件及各自职责范围。

## 输出格式

每个 skill 文件输出如下结构：

```markdown
---
name: <动名词形式，如 managing-api-conventions>
description: Use when <具体触发条件>. <第三人称，不含工作流摘要>
---

## 项目约定

- <约定1>
- <约定2>

## 协作偏好

- <偏好1>
- <偏好2>

## When NOT to use

- <该文件不覆盖的内容，标明边界>

---

> 保存路径：~/.claude/skills/<project>-skills/<filename>.md
```

### Description 字段规范

- 以 "Use when..." 开头
- 只写触发条件，不写工作流程或处理步骤
- 第三人称
- 不超过 500 字符
- 包含可被搜索的具体关键词（项目名、场景词）

### 命名规范

- 动名词形式（gerund）：`managing-conventions` 而非 `conventions`
- 用连字符，全小写
- 体现职责范围，不用泛称（避免 `utils` / `misc`）

### 行数约束

- 单个 SKILL.md 不超过 200 行
- 超出时拆出 `reference/` 子文件，SKILL.md 保留总览和链接
- 子文件引用只能一层深，不允许嵌套引用

## 实现组件

### 组件 1：`~/.claude/skills/session-to-skill/SKILL.md`

Skill 本体，定义：

- 触发条件判断逻辑
- 提炼规则
- 分类路由决策树
- 输出格式模板

### 组件 2：`~/.claude/CLAUDE.md` 追加触发规则

```
当对话到达自然结束点时，调用 session-to-skill skill，
从本次对话提炼项目约定和协作偏好，以 markdown 展示在响应末尾。
```

---

## 不在范围内（v1）

- 不自动写入文件系统（用户手动保存）
- 不读取 JSONL 历史转录（仅使用当前对话上下文）
- 不支持跨会话合并（v2 考虑）
- 不生成测试用例或验证脚本

---

## 未来版本方向（备忘）

- **v2**：读取 JSONL 转录，支持跨会话内容合并到已有 skill 文件
- **v2**：去重时做语义相似度判断，而非纯文本匹配
- **v3**：条件触发模式（C 方案），在对话中途检测高价值信号并预标记
